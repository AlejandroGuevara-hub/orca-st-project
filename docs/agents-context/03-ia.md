# Contexto de IA

## Propósito

Definir cómo se integran modelos de IA, se gestionan prompts, contexto, herramientas y evaluación. Aplica a agentes que construyan funcionalidades con LLMs o sistemas de IA.

## Estado

- Sin proveedor de modelos ni SDK elegido.
- Registrar proveedor, modelos y límites de costo antes de implementar.

## Principios

- La IA es un componente del sistema, no una caja negra: debe tener contrato, validación y manejo de fallos.
- Prompts versionados y revisables.
- Resultados deterministas cuando el caso lo requiera (temperatura baja, semillas si aplica).
- Privacidad por defecto: minimizar datos enviados al modelo.
- Todo output del modelo se trata como entrada no confiable.

## Gestión de prompts

- Guardar prompts en archivos versionados, no embebidos en múltiples lugares.
- Separar instrucciones de sistema, contexto y entrada del usuario.
- Documentar variables de entrada y formato esperado de salida.
- Cambiar un prompt es un cambio de comportamiento: requiere prueba y revisión.

## Contexto y ventana

- Medir tokens antes de enviar; truncar o resumir de forma explícita.
- Priorizar información relevante y descartar ruido.
- Evitar duplicar el mismo contexto en múltiples turnos.
- Definir estrategia de memoria: ninguna, resumen o recuperación (RAG).

## Salidas estructuradas

- Preferir formatos parseables (JSON con esquema).
- Validar el output contra un esquema y manejar el fallo.
- Nunca ejecutar código generado sin sandbox y revisión.

## Herramientas y agentes

- Definir herramientas con contratos claros y validación de argumentos.
- Limitar permisos al mínimo necesario.
- Establecer límites de iteraciones, tiempo y costo.
- Registrar las decisiones y llamadas relevantes para auditoría.

## Seguridad y guardrails

- Filtrar instrucciones maliciosas y entradas no confiables.
- No incluir secretos en prompts ni en contexto.
- Prevenir exfiltración de datos mediante instrucciones del usuario.
- Definir qué hacer ante contenido peligroso o fuera de política.

## Evaluación

- Mantener un conjunto de casos de prueba representativos.
- Medir calidad, latencia y costo por caso.
- Comparar cambios de prompt o modelo contra una línea base.
- Documentar regresiones conocidas.

## Costo y límites

- Registrar consumo por operación.
- Definir límites por usuario, sesión o tarea.
- Preferir modelos más pequeños cuando la calidad lo permita.

## Checklist antes de entregar una feature de IA

- [ ] Prompt versionado y documentado.
- [ ] Output validado y fallos manejados.
- [ ] Sin secretos ni datos sensibles innecesarios.
- [ ] Límites de costo y tiempo definidos.
- [ ] Casos de evaluación actualizados.
- [ ] Revisión de seguridad de entradas y herramientas.
